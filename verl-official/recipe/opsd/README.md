# Search-OPSD：检索增强推理的策略内自蒸馏

本 recipe 实现 Search-OPSD 的 OPSD 阶段，从已有的 Search-R1 GRPO 检查点出发。当前实验使用 Qwen2.5-3B Base，评测结果需独立验证。

## 方法

1. 用冻结策略为每个问题生成多条轨迹，记录模型输出、检索结果和答案正确性。
2. 在同一问题内，优先选择检索次数最少、轨迹最短的正确样本作为参考，再选择与参考差异最大的其他轨迹作为学生样本，优先从错误轨迹中选取。没有合适配对的问题跳过。
3. 教师额外看到参考轨迹，学生只看到原问题；两者在同一条学生轨迹的生成位置上计算全词表前向 KL。检索器插入的内容仅作为上下文，不计入损失。教师使用冻结底座，学生通过 LoRA 更新。
4. 按留出验证集的答案精确匹配率（EM）选出最佳 adapter，再与底座合并。测试集仅用于最终评估。

## 运行与配置

准备可用的模型检查点、问答数据和检索服务。CLI 入口为 `python -m recipe.opsd --help`，运行顺序为 `prepare → collect → mine → train → merge`；可用 `evaluate` 单独评估。批量采样入口为 `python -m recipe.opsd.rollout_vllm --help`。

- **采样配置**：每题 5 条轨迹，温度 1.0，最多检索 4 次；上下文上限 8192，新生成 token 上限 2048。
- **训练配置**：1 个 epoch，全局 batch 560 对；总优化器步数为 `ceil(有效配对数 / 560)`，尾批也更新。
- **保存配置**：每 10 个优化器 step 保存一次，并保存最终权重；合并时读取 `best.json` 指向的 adapter。

主要实现：`rollout.py` 和 `rollout_vllm.py` 负责采样，`core.py` 负责轨迹配对和 token 对齐，`loss.py` 与 `train.py` 负责蒸馏损失和训练。
